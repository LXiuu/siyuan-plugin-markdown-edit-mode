> 状态：阶段 0～2 已实现；标准 Markdown 叶子类型、容器内容和 GFM 表格已完成风险分级与隔离验证，结构级增删移动仍待阶段 3

## 0. 当前实现状态

截至 2026-07-22，首个可用版本已经落地：

- 默认读取顶层内容块和文档 Kramdown，生成连续 Markdown 投影；块 IAL 和真实块边界不暴露为普通可删文本。
- 段落、ATX 标题、围栏代码、数学、分隔线、普通 HTML 可直接编辑，并支持已验证安全的叶子类型转换；普通叶子块也可转换为列表或引述。
- 列表、任务列表、嵌套列表和引述通过 AST 映射到真实后代块，只更新发生变化的段落或列表项控制块；GFM 表格支持单元格、转义管道、增删行列和对齐。
- 超级块、Callout、查询嵌入、数据库、iframe、视频、音频、挂件及未知块型显示为原子保护卡片。
- 延续接近 Typora 的 1 秒延迟自动保存，但只按块 ID 更新变化块或容器后代，不更新文档根。
- 写入时附回原块 IAL；保存前检测服务器快照并创建备份，保存后校验顶层 ID / 顺序 / 预期类型、Markdown 语义、完整容器树和全部 IAL。
- 代码围栏、标题闭合 `#`、分隔线和表格排版允许被 SiYuan 规范化，比较采用语义等价；Setext 标题和缩进代码因 SiYuan 3.7.3 的解析差异而阻止引入。
- 当前仍不支持新增、删除、拆分、合并、移动顶层块；已有列表/引述的增删项、重排、改嵌套和转出容器，以及表格跨类型转换会因 ID/IAL 风险被拒绝。
- 块 API 不可用时才降级到旧标准 Markdown 模式，首次写入前显示有损风险确认。

真实验证全部使用 API 创建并自动删除的一次性临时笔记本，覆盖安全叶子类型转换、列表后代精确更新、任务勾选、嵌套列表、引述、表格行列/对齐/转义管道、HTML 与代码围栏规范化。样本笔记本始终只读。当前自动测试为 25 项，另有独立 API 往返脚本。

## 1. 结论与设计决策

当前插件不能在既有保存链路上直接增加“数据库块、查询嵌入、超级块”等语法适配。问题不只是少数特殊块无法导出，而是现有链路会把整个文档根作为标准 Markdown 写回，进而重建其一级子块。即使用户只改一个字，未编辑块的 ID、IAL、属性和引用关系也可能被改写或丢失。

推荐采用以下产品与技术方向：

1. 默认新增“安全块模式”：读取 SiYuan Kramdown，维护带块 ID 的文档快照，在 CodeMirror 中展示干净的 Markdown 投影，并把暂不支持的结构渲染为不可破坏的原子块。
2. 保存从“整篇覆盖”改成“块级补丁”：已存在的安全叶子块使用 `updateBlock`，新增、删除和移动分别使用 `insertBlock`、`deleteBlock`、`moveBlock`；安全模式永远不对文档根执行整篇 `updateBlock`。
3. 数据库、查询嵌入、超级块、复杂容器先做到“可见、可定位、不可误写”，再逐类提供专用编辑器。未知块型一律按受保护块处理。
4. 安全块模式保留 1 秒延迟自动写回，以维持连续源码编辑体验；每次写入都必须经过块边界校验、并发快照检查、保存前备份和保存后不变量校验，`Ctrl+S` / `Esc` 用于刷新待保存修改并退出。
5. 现有标准 Markdown 模式只能保留为明确标注“有损”的兼容模式，首次写入前必须二次确认；不能再把它称作安全的 SiYuan 源码编辑。

本方案对“兼容”的最低定义不是“能显示成某种 Markdown”，而是：

- 未修改块的 ID、父子关系、顺序、IAL、查询源码、数据库关联、布局语义和资源引用保持不变；
- 已修改块的变化仅限于用户明确编辑的内容；
- 无法证明安全的块禁止写回，不做静默降级；
- 文档在打开期间被其他窗口、插件或同步修改时，不覆盖外部变化；
- 任一步骤失败后存在可恢复快照，并能指出可能受影响的块。

## 2. 旧有损链路为什么会损坏内容

### 2.1 旧有损读写链路

~~~mermaid
flowchart LR
    A["/api/export/exportMdContent"] --> B["发布用标准 Markdown"]
    B --> C["去 front matter / 标题 / Unicode 归一化"]
    C --> D["CodeMirror 全文编辑"]
    D --> E["1 秒 debounce 实时保存"]
    E --> F["/api/block/updateBlock<br/>目标 = 文档根"]
    F --> G["删除一级子块并重新解析、插入整棵树"]
~~~

仓库中的对应实现：

- `src/api.ts::exportMdContent` 使用 `/api/export/exportMdContent`；
- `src/api.ts::updateBlockByMarkdown` 对文档根调用 `/api/block/updateBlock`；
- `src/index.ts` 的 `REALTIME_SAVE_DELAY` 为 1000 ms；
- `src/index.ts::confirmWriteRisk` 现在只在有损降级模式首次写入前调用；
- `src/markdown.ts::normalizeMarkdownForSave` 对全文替换 NBSP，并删除 U+200B 至 U+200D 和 BOM。

### 2.2 当前默认安全链路（已实现）

~~~mermaid
flowchart LR
    A["getChildBlocks + getBlockKramdown"] --> B["连续 Markdown 投影 + 保护范围"]
    B --> C["CodeMirror 普通编辑 / 锁定源码 / 原子卡片"]
    C --> D["1 秒 debounce"]
    D --> E["类型、围栏、块边界和服务器快照校验"]
    E --> F["仅对变化块或容器后代 updateBlock，并附回原 IAL"]
    F --> G["重新读取并校验顺序、Markdown 和 IAL"]
~~~

该链路不调用文档根 `updateBlock`。当 Kramdown 的 IAL 属性只发生顺序重排时按语义等价处理；正文、属性值、块 ID、类型、数量或顺序发生变化时仍判定为外部冲突。

### 2.3 标准 Markdown 导出不是可写回的块源码

SiYuan 官方源码显示，标准 Markdown 导出会显式关闭 Kramdown IAL：

~~~text
SetKramdownIAL(false)
~~~

同一导出流程还会：

- 按导出设置展开或替换查询嵌入；
- 去除超级块的行/列布局标记；
- 把属性视图（数据库）转换成静态 Markdown 表格；
- 根据 `refMode`、`embedMode`、YAML front matter 等导出设置生成不同结果。

因此，`exportMdContent` 的结果适合发布或复制，不是稳定的双向序列化格式。把它重新解析回 SiYuan，无法恢复导出前被丢弃的结构。

### 2.4 文档根更新会扩大损坏范围

SiYuan 官方 `kernel/api/block_op.go` 中，更新文档根的分支会先删除该文档的全部一级子块，再把新解析出的树整体插入。标准导出又不带 IAL，所以旧子块 ID 没有可复用依据。

直接后果包括：

| 风险 | 当前链路的结果 |
| --- | --- |
| 子块 ID | 即使内容没改，也可能整体重建 |
| 块引用 | 指向旧 ID 的引用可能失效 |
| 块 IAL / Span IAL | 标准导出不携带，写回后丢失 |
| style、fold、自定义属性 | 可能丢失或被规范化 |
| 数据库 | 动态属性视图被静态表格替代 |
| 查询嵌入 | SQL 源码可能被查询结果替代 |
| 超级块 | 行列布局标记被移除，退化为普通块 |
| 列表等容器 | 子项层级和子块 ID 可能重建 |
| 代码内容 | NBSP、ZWJ、零宽字符等会被全局归一化 |
| 并发编辑 | 打开后发生的外部修改可能被整篇覆盖 |

另外，当前 front matter 清理根据 `title/date/lastmod` 三个键判断 SiYuan 导出元数据。用户自己编写且恰好包含这些键的合法 YAML 也存在被误删的可能。该清理只应留在有损导出模式，不能用于 Kramdown 或块级安全模式。

## 4. 兼容等级与块型策略

### 4.1 兼容等级

| 等级 | 含义 |
| --- | --- |
| C0 受保护 | 能识别、显示摘要、原样往返；不能在 Markdown 投影中直接修改 |
| C1 内容可编辑 | 保留块身份和属性，仅编辑单块正文 |
| C2 结构可编辑 | 支持插入、删除、移动、拆分、合并及递归子块 diff |
| C3 语义可编辑 | 使用专用 UI 编辑查询、Callout、布局等 SiYuan 专有语义 |

任何未知节点默认 C0。只有通过对应版本的无损测试后，才能把块型提升到更高等级。

### 4.2 兼容矩阵

| 块或构造 | 当前模式风险 | 推荐首期等级 | 保存策略 | 后续方向 |
| --- | --- | --- | --- | --- |
| 文档根 | 更新时重建全部一级子块 | C0 | 安全模式禁止对根执行整篇更新 | 只作为快照、并发检测和导航边界 |
| 段落 | 整篇更新会重建身份；单块更新安全 | C1 已实现 | 按原块 ID 更新并附回 IAL；允许转为已验证安全的叶子、列表或引述 | C2 支持拆分、合并和调序 |
| 标题 | 整篇更新可能重建 ID | C1 已实现 | ATX 标题单块更新；允许改级别及安全转为其他叶子 | C2 支持移动；Setext 等待内核兼容 |
| 代码块 | 全局 Unicode 清理会改正文；IAL 丢失 | C1 已实现 | 围栏闭合校验，按语言与代码正文做语义比较，允许围栏规范化 | 提供语言选择；缩进代码等待内核兼容 |
| 数学块 | 源码和 IAL 可能丢失 | C1 | 原子叶子块更新 | 增加公式预览 |
| 分隔线 | ID 会重建 | C1 | 按块 ID 更新或显式插入/删除 | 无需专用编辑器 |
| 列表 / 列表项 | 更新列表根会重建全部后代 | C1 内容/控制已实现，结构 C0 | AST 映射到真实后代段落或列表项；保留整棵树 ID/IAL；增删、重排、改嵌套拒绝 | C2 用 insert/delete/move 支持结构编辑 |
| 引述块 | 更新引述根会重建后代 | C1 内容已实现，结构 C0 | 只更新匹配的真实后代叶子并验证完整树 | C2 支持增删、重排和类型转换 |
| 表格 | 跨类型会增删 `colgroup` IAL；源码会被重排 | 受限 C2 已实现 | 合法 GFM 表格可编辑单元格、转义管道、行列、对齐；用 AST 语义比较；跨类型拒绝 | 评估非 GFM 单元格属性与专用编辑 |
| Callout | 专有类型和结构可能退化 | C0，随后 C3 | 保留原始 Kramdown 和所有属性 | 专用类型、标题、正文编辑器 |
| 超级块 | 标准导出主动删除布局标记 | C0 | 原始 Kramdown 原子保护，投影中显示布局摘要 | C3 布局编辑器；不允许纯文本误改边界 |
| 查询嵌入 | SQL 可能被结果替代 | C0，随后 C3 | 永远保存原始查询节点，结果只读展示 | 专用 SQL 编辑、预览和校验 |
| 数据库 / 属性视图 | 被导出成静态表格，关联可能永久丢失 | C0 | 锁定 `NodeAttributeView`、`data-av-id` 及视图属性；提供“回到 SiYuan 编辑” | 暂不承诺 Markdown 内编辑数据库 |
| HTML 块 | 专有媒体标签可能转成其他块型 | C1 普通 HTML 已实现 | 仅放行保持普通 HTML/安全叶子语义的单块；iframe/video/audio/widget 单独保护 | 扩展 CommonMark HTML 类型矩阵 |
| 图片 | 资源 URL 可保留，但块/Span 属性会丢失 | C1 或 C0 | 简单图片可编辑 alt/URL；带复杂 IAL 的图片锁定 | 专用资源选择与属性编辑 |
| video / audio / iframe | 可能退化为 HTML 或普通链接 | C0 | 保留节点类型、URL、IAL 和属性 | 专用媒体属性编辑 |
| 块 IAL | 标准导出完全丢弃 | C0 | 存在规范快照中，默认不作为普通文本开放 | 高级属性面板 |
| Span IAL | 标准导出完全丢弃 | C0 | 解析为行级 token，未编辑时原样保留 | token-aware 行级编辑 |
| 块引用 | 旧 ID 失效会断链 | C1 | 引用目标 ID 作为 token 保护；显示文本可独立处理 | 保存前验证目标存在及删除影响 |
| style / fold / 自定义属性 | 写回后可能丢失 | C0 | 与块快照绑定，不参与普通 Markdown 清理 | 专用属性面板 |

## 5. 候选方案比较

| 方案 | 优点 | 根本问题 | 结论 |
| --- | --- | --- | --- |
| 标准 Markdown 整篇编辑 + 文档根更新 | 实现简单，编辑体验自由 | 导出层已丢失 SiYuan 结构，根更新扩大损坏范围 | 拒绝作为安全模式；只能保留为有损兼容模式 |
| 完整 Kramdown 文本编辑 + 文档根更新 | IAL、查询和超级块可见 | 用户可误删 ID/IAL；根更新仍会重建树；数据库和容器复用 ID 的行为尚未验证 | 仅做隔离实验或高级模式，不作为默认方案 |
| Kramdown 规范快照 + Markdown 投影 + 块级补丁 | 能把编辑体验与真实持久化格式分离，最小化修改范围 | 需要解析、投影映射、结构 diff 和较完整的验证系统 | 推荐主方案 |
| 特殊块回到原生编辑器 | 安全、实现成本低 | 不能在一个纯文本面板内编辑所有语义 | 与主方案组合，尤其适用于数据库 |

“完整 Kramdown 整篇写回能否复用显式 ID”必须在一次性副本文档中单独验证。即使实验结果为真，也不能据此假设所有 SiYuan 版本、所有容器和数据库块都无损。

### 6.1 读取与规范快照

安全模式使用 `/api/block/getBlockKramdown` 获取保留 IAL 的内容，不使用 `exportMdContent` 作为规范源。

`DocumentSnapshot` 至少包含：

- 文档 ID、获取时间、SiYuan 版本和内容 hash；
- 每个块的 ID、类型、子类型、父 ID、根 ID、兄弟顺序；
- 原始 Kramdown、正文区域、块 IAL 和行级 token；
- 是否可编辑、所属保护容器、投影起止位置；
- 查询源码、数据库 ID、超级块布局等专有字段；
- 保存前后需要保持的“不变量签名”。

层级信息优先使用官方块 API，例如 `getChildBlocks`。若官方 API 无法以可接受的调用次数提供完整树，再评估版本受控的只读 SQL；不能把数据库表结构当作无版本约束的公共协议。

### 6.2 投影层

CodeMirror 中展示的是“编辑投影”，不是直接要整篇写回的字符串：

- 已验证安全的标准 Markdown 块与容器展示为正常 Markdown；
- IAL、块边界和内部映射保存在状态字段中，不让普通文本操作随意删除；
- 数据库、查询、超级块等使用 CodeMirror widget 显示类型、摘要、ID 和操作入口；
- 受保护块使用 `atomicRanges`/事务过滤阻止跨边界删除、粘贴和替换；
- 复制可以输出友好的 Markdown 摘要，但粘贴回来不能冒充原特殊块；
- 未识别块仍能以“未知 SiYuan 块”占位并原样保存。

不要把可删除的 HTML 注释当作唯一保护机制。哨兵可以用于内部调试，但真实 Kramdown 必须保存在投影之外。

### 6.3 变更计划与块级写入

首个可写版本限制变更范围：

- 支持段落、ATX 标题、围栏代码、数学、分隔线、普通 HTML 的编辑与安全类型转换；普通叶子还可转为列表或引述；
- 首版禁止新增、删除、移动；这些操作将在阶段 3 通过显式编辑命令生成，不从任意全文重排中猜测；
- 不允许一次文本选择跨越受保护边界；
- 列表/引述允许不改变子树的内容和控制标记修改；表格允许合法 GFM 语义编辑；会删除或重建既有后代的结构修改继续保护。

保存计划按操作分类：

| 变化 | API | 约束 |
| --- | --- | --- |
| 修改已有安全叶子块 | `updateBlock` | 目标必须是该块 ID，不得是文档根；保存后验证 ID 和属性 |
| 新增块 | `insertBlock` / prepend / append | 记录服务端返回的新 ID，并更新投影映射 |
| 删除块 | `deleteBlock` | 先检查入链引用和保护容器 |
| 移动块 | `moveBlock` | 验证父子类型是否合法，并检查最终顺序 |

SiYuan 暂无可依赖的公开多操作原子事务承诺，因此执行器应：

1. 保存前落一份完整快照；
2. 按依赖顺序执行最少操作；
3. 第一个失败立即停止，不继续扩大变化；
4. 重新读取服务器状态，生成已成功/未执行/状态不明列表；
5. 提供恢复或手工处理入口。

### 6.4 并发与冲突

当前首版采用保守的规范快照比较：只要服务器端正文、属性值、块集合、类型或顺序变化，就停止本次写入；仅忽略 IAL 属性的无语义顺序重排。块级三方合并尚未实现，因此不会自动合并两个窗口的变化。

后续版本再按块 hash 将比较结果分三类：

- 用户未改、服务器已改：采用服务器版本并刷新投影；
- 用户已改、服务器未改：正常写入；
- 双方都改同一块：停止该块写入，展示三方差异；
- 双方修改不同块：允许合并，但仍需重新计算结构位置。

不能只比较整个文档文本，因为数据库结果或其他动态展示可能变化；应比较规范 Kramdown和块级签名。

### 6.5 规范化边界

`normalizeMarkdownForSave` 需要拆成语法区域感知的转换：

- 行尾统一只能作用于编辑器结构层；
- 代码块正文、HTML、查询源码、URL 和原始受保护块不做 NBSP/零宽字符清理；
- 空段落标记只在明确的段落节点上生成；
- front matter / 重复文档标题清理只属于旧的有损导出模式；
- 每次规范化都应有输入区域类型，不再对整篇字符串做盲目替换。

### 6.6 快照与恢复

快照写入插件自己的数据空间，使用 SiYuan 插件 API，不直接修改 `workspace/data`。当前实现每次写入前覆盖保存最近一份 `last-block-source-backup.json`；后续恢复界面完成后再扩展为：

- 最近 5 次成功保存前快照；
- 最近 1 次失败操作的快照和操作日志；
- 文档 ID、版本、hash、完整 Kramdown、块树元数据；
- 恢复前的二次快照，避免恢复操作覆盖当前状态。

快照不是安全写入的替代品，但它是多 API 操作缺少原子性时的最后保护。

## 7. 用户交互方案

### 7.1 默认安全块模式

- 状态栏显示“内容块安全更新”、可编辑 / 已保护块数量及保存结果；
- 数据库、查询、超级块等显示为有边框的原子卡片，包含类型、块 ID 和摘要；
- 列表、引述和表格保留普通 Markdown 外观；安全内容编辑自由输入，只有实际改变受保护子树或 IAL 的事务/保存被拒绝；
- 标准 Markdown 块连续编辑，1 秒后自动按块或后代保存；`Ctrl+S`、`Esc`、双击 `Ctrl` 会刷新待保存修改并退出；
- 触及保护块、块间分隔区或跨块选区的事务整体拒绝；
- 离开时若未修改则零写请求；保存后展示块数和验证成功状态。

### 7.2 旧标准 Markdown 模式

若继续保留当前自由全文编辑，应重命名为“有损标准 Markdown 模式”，并满足：

- 仅在安全块 API 加载失败时自动降级，并显示明显错误状态；
- 保留 1 秒延迟写回以兼容现有交互，但第一次写入前调用风险确认；
- front matter、重复标题和粘贴去围栏只在该模式处理；
- 仍按整篇文档根更新，因此不能承诺保留数据库、查询、超级块、IAL 和引用；
- 后续应增加显式禁用开关和更细的风险统计。

仅弹一次通用确认框不足以让当前算法变安全，它只是防止用户在不知情时触发有损操作。

## 9. 无损验证方案

### 9.1 保存前后不变量

每次自动化测试都应比较：

1. 未修改块 ID 集合完全相等；
2. 块的 parent、root、排序关系不变；
3. 未修改块的规范 Kramdown hash 不变；
4. 块 IAL、Span IAL、style、fold、name、memo、bookmark 和自定义属性不变；
5. 查询 SQL 原文不变，不能变成查询结果；
6. 超级块的 col/row 边界和嵌套不变；
7. `data-av-id`、视图属性及数据库原生可用性不变；
8. 块引用目标仍存在，入链和出链数量符合预期；
9. 资源 URL、节点类型和资源可访问性不变；
10. 代码正文除用户编辑区外逐字符相同；
11. 保存后重新加载的投影与编辑器预期一致；
12. 无修改打开并退出时，零写请求、零历史记录变化。

## 11. 已确定事项与待验证问题

### 已确定

- 安全模式不使用标准 Markdown 导出作为写回源；
- 安全模式不对文档根执行整篇更新；
- 安全块模式保留 1 秒延迟自动保存，但只更新变化块或容器后代，并在每次写入前后执行安全校验；
- 标准 Markdown 默认可编辑；只有会改变既有 ID、IAL、父子层级或无法按 SiYuan 实际类型验证的修改才拒绝；
- 数据库、查询、超级块、Callout、媒体、挂件和未知块型默认受保护；
- 所有访问通过 SiYuan API，插件不直接读写 `workspace/data`；
- 当前可写范围包括安全叶子类型、列表/引述内容与控制标记、合法 GFM 表格语义；结构增删移动仍受保护；
- 原样打开和关闭必须零写入。

### 已验证

- SiYuan 3.7.3 单叶子块更新在附回原 IAL 时能保留块 ID、顺序、style、fold 和自定义属性；段落、ATX 标题、代码、数学、分隔线、普通 HTML 间的安全类型转换保留根 ID/IAL。
- 更新列表或引述根会重建全部后代；精确更新真实后代段落、任务列表项控制标记可保留整棵树的 ID、顺序、层级、IAL 和自定义属性。
- GFM 表格的单元格、转义管道、增删行列和对齐更新保留根 ID/IAL；表格跨类型会增删 `colgroup` 属性，因此拒绝。
- 同一文档 Kramdown 多次读取会随机重排块 IAL 属性，当前比较器已按属性映射判断语义等价。
- 代码围栏字符或长度会被内核规范化为反引号，标题闭合 `#`、分隔线和表格排版也会被规范化；当前均按 AST/内容语义验证，不锁定写法。
- Setext 标题、缩进代码、HTML comment/script/style 在 SiYuan 3.7.3 中实际创建为段落；iframe/video/audio 创建为专有块，检测器按真实类型保护。
- 隔离往返脚本创建并自动清理临时笔记本；用户样本只读，未发生直接文件写入。

### 待验证

1. SiYuan 3.7.3 对带显式 IAL 的根 Kramdown 更新，实际会复用哪些 ID；该实验只用于理解行为，不改变“安全模式禁止根更新”的决策。
2. 容器增删/移动/拆分/合并等结构操作，以及各类复杂 Span IAL / 块引用的完整不变量。
3. `getBlockKramdown` 与层级 API 在 2500+ 块文档上的性能，以及是否需要按可视区懒加载。
4. 宿主提供的 Lute 版本和 TypeScript 可用接口，是否足以稳定解析所有当前节点。
5. 多个块操作是否存在可公开依赖的事务 API；在确认前按“无原子事务”设计。
6. 用何种稳定字段做外部修改检测；若依赖 SQL 的 `updated` 字段，需要版本门控和 hash 复核。
7. 插件最低支持的 SiYuan 版本，以及版本升级后如何自动降级未知块型。

任何待验证项失败时，正确的降级路径都是“保持只读并解释原因”，不是退回整篇标准 Markdown 覆盖。
